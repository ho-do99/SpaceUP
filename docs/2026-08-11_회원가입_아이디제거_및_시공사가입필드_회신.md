# 회원가입 username 제거 + 시공사 가입 필드 회신

작성일: 2026-08-11
대상 브랜치: `backend` (push 완료, 커밋 `172e4b9`)

---

## 1. username 제거 → 로그인 식별자는 email로 통일

말씀하신 대로 `username`을 완전히 없앴습니다. 별도 아이디 개념 자체가 사라졌고, **email이 로그인 식별자**입니다.

| 변경 전 | 변경 후 |
|---|---|
| `POST /api/member/join` Body에 `username` 필수 | `username` 필드 삭제 (더 이상 안 보내도 됨) |
| `POST /api/member/login` Body `{username, password}` | `{email, password}` |
| `MemberResponse`에 `username` 필드 | 삭제 |

`Member.email`에 유니크 제약을 새로 걸었습니다(기존엔 `username`에만 있었음). 이메일 중복 가입 시 기존과 동일하게 409로 처리됩니다.

## 2. 회원가입 성공 시 토큰 반환

3가지 안 중 **"join 성공 시 token 반환"**으로 진행했습니다. `POST /api/member/join` 응답이 로그인과 동일한 `LoginResponse` 구조로 바뀌었습니다.

```json
{
  "success": true,
  "message": "회원가입이 완벽하게 완료되었습니다.",
  "data": {
    "accessToken": "eyJ...",
    "memberId": 42,
    "role": "CONTRACTOR"
  }
}
```

가입 직후 이 `accessToken`으로 바로 `PUT /api/contractors/me` 등 온보딩 API를 호출하면 됩니다. 별도 온보딩 전용 API나 join 요청에 업체정보를 끼워 넣는 방식은 채택하지 않았습니다 — 계정(Member)과 업체 프로필(ContractorProfile)의 저장 시점을 분리하는 게 기존 구조(계정 생성 → 프로필은 upsert로 별도 관리)와 더 맞다고 판단했습니다.

## 3. 시공사 가입 화면 필드 — 저장 API 추가

`PUT /api/contractors/me`(`ContractorProfileUpdateRequest`)에 아래 5개 필드를 추가했습니다. 기존 필드(`businessRegistrationNumber`, `companyName`, `activityRegions` 등)와 같은 요청/응답에 포함됩니다.

```json
{
  "businessRegistrationNumber": "123-45-67890",
  "representativeName": "홍길동",
  "businessRegistrationCertificateUrl": "/api/files/business-documents/xxxx.pdf",
  "companyName": "스페이스업 인테리어",
  "companyAddress": "광주 서구 상무중앙로 1",
  "businessAddress": "광주 서구 상무중앙로 1",
  "constructionExperienceYears": 10,
  "activityRegions": "광주 북구,광주 서구",
  "travelDistanceKm": 30,
  "specialties": "도배,바닥재,조명",
  "portfolioUrl": "https://example.com/portfolio",
  "introduction": "10년 경력의 인테리어 전문 업체입니다."
}
```

| 필드 | 타입 | 비고 |
|---|---|---|
| representativeName | string | 대표자명 |
| businessRegistrationCertificateUrl | string | 아래 4번 업로드 API 응답값을 그대로 저장 |
| companyAddress | string | 업체 주소 |
| businessAddress | string | 사업장 주소 |
| constructionExperienceYears | number | 시공 경력(년) |

## 4. 사업자등록증 업로드 API — 신규 구현

기존 이미지 업로드(`/api/files/images`)는 JWT 필요 + 이미지만 지원이라, 회원가입 전(계정 없음) 단계에서 쓸 수 있는 **별도 공개 API**를 새로 만들었습니다.

- `POST /api/files/business-documents` — **인증 불필요**, multipart `file`. JPG/PNG/PDF만 허용, **최대 10MB**(초과 시 400). 응답: `{"fileUrl": "/api/files/business-documents/{파일명}"}`
- `GET /api/files/business-documents/{파일명}` — 인증 불필요, 파일 그대로 반환

가입 순서 제안:
1. 사업자등록증 파일을 `POST /api/files/business-documents`로 먼저 업로드 → `fileUrl` 획득
2. `POST /api/member/join`으로 회원가입 → `accessToken` 획득
3. 그 토큰으로 `PUT /api/contractors/me` 호출, 1번에서 받은 `fileUrl`을 `businessRegistrationCertificateUrl`에 넣어 나머지 업체정보와 함께 저장

> ⚠️ 지금은 업로드된 파일을 UUID 파일명만 알면 누구나 조회 가능합니다(기존 이미지 업로드와 동일한 방식). 사업자등록증은 포트폴리오 사진보다 민감한 문서라, 나중에 조회에도 인증을 걸지 검토가 필요할 수 있습니다 — 우선 급한 대로 기존 패턴과 동일하게 맞췄습니다.

## 5. 사업자등록번호 확인(진위확인) API — 없음, 확인 필요

찾아본 결과 **백엔드에 사업자등록번호를 검증하는 API가 전혀 없습니다.** 국세청 "사업자등록정보 진위확인 및 상태조회" 같은 외부 공공 API 연동이 필요한 신규 기능이라, 이번 범위에서는 만들지 않았습니다.

이 기능이 실제로 필요하면 별도로 알려주세요 — data.go.kr에서 서비스키 발급받는 것부터 시작해야 해서(이번에 삭제한 국토부 실거래가 연동과 비슷한 구조) 별도 작업으로 진행하는 게 맞을 것 같습니다.
