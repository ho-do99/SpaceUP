## 5. 다중 시공사 프론트 실API 연결

### 목표

- 기존 화면 디자인과 담당자 테스트 흐름을 보존하면서 다중 시공사 조회·채팅·견적 비교·최종 선택을 실API에 연결한다.
- 실API 로딩 또는 연결 실패가 기존 화면 전체 장애로 번지지 않도록 단계적으로 연결한다.

### 실제 변경 내용

- 임대인 견적 요청 내역과 상세 화면이 로그인 사용자의 실제 의뢰·견적 API를 우선 조회하도록 연결했다.
- 상세 화면에 시공사별 견적 목록, 시공사별 독립 채팅 진입, 최종 견적 선택 기능을 연결했다.
- 임대인 채팅 화면을 추가하고 `(requestId, contractorId)` 단위로 메시지를 조회·전송하도록 연결했다.
- 시공사 채팅 목록과 채팅 상세 화면을 실제 채팅 API에 연결했다.
- 견적 응답에서 화면에 시공사명을 표시할 수 있도록 백엔드 `ContractorQuoteResponse`에 `contractorName`을 추가했다. 기존 필드는 삭제하거나 의미를 바꾸지 않았다.
- 실제 API가 아직 연결되지 않았거나 호출에 실패하면 기존 담당자가 사용하던 예시 데이터를 유지하도록 fallback을 남겼다.
- DB 스키마와 데이터는 변경하지 않았다.

### 기존 담당자 흐름 보호

- 기존 문자열 기반 예시 URL과 목데이터 화면은 그대로 동작한다.
- 숫자 의뢰 ID로 접근할 때만 실데이터 흐름을 사용한다.
- 시공사 채팅의 기존 현장 방문·견적 작성 버튼은 예시 흐름에서 유지했다. 실데이터 채팅에서는 아직 연결하지 않은 화면으로 잘못 이동하지 않도록 숨기고 후속 단계임을 표시했다.
- 임대인 채팅은 경쟁 시공사 메시지가 섞이지 않도록 반드시 `contractorId`를 포함한다.

### 검증 결과

- 프론트 API 계약 테스트와 의뢰 화면 변환 테스트를 추가했다.
- 프론트 전체 테스트 23건과 프로덕션 빌드를 통과했다.
- 백엔드 전체 테스트 111건을 통과했고 1건은 기존 설정대로 제외됐다.
- Vite가 약 730KB 메인 청크에 대해 크기 경고를 표시하지만 빌드 실패나 이번 기능의 회귀는 아니다. 추후 화면 단위 코드 분할이 필요하다.

### 남아 있는 범위

- 시공사 의뢰 목록·상세·참여 승인/거절 화면은 아직 실API 연결이 필요하다.
- 현장 방문 일정 등록과 견적 작성 화면은 기존 예시 흐름을 유지한다.
- 현재 실DB에는 비교 가능한 여러 견적·채팅 데이터가 충분하지 않으므로, 화면에서 다중 비교 모습을 확인하려면 정상 업무 흐름으로 데이터를 만들거나 별도 승인 후 테스트 데이터를 넣어야 한다.

- 관리자 대시보드 응답에는 `totalMaterialVendors`, `pendingMaterialVendorApprovals`가 남아 있고 서비스는 두 값을 항상 0으로 반환한다.
- 회원가입 검증 문구, 관리자·정산 주석, 추천 자재 DTO/프론트 타입의 `vendorName` 등 자재업체 표현이 남아 있다.

### 확인된 데이터 현황

- `material_product`는 정확히 36건이다. `information_schema.TABLE_ROWS`가 60으로 보였던 값은 InnoDB의 부정확한 추정치다.
- 4개 테마 × 3개 작업 종류 × 3개 가격 단계 구성이 맞다.
- `boards`, `comments`, `upload_files`, `contractor_projects` 관련 현재 실데이터 삭제는 없다.

### 수정 우선순위

1. 백엔드 활성 엔티티 5개와 실DB 사이의 스키마 누락을 명시적 마이그레이션으로 해소한다.

3. 자재업체용 관리자 응답 필드·검증 문구·정산 명칭·추천 DTO 잔재를 현재 역할 모델에 맞게 정리한다.
4. 전체 외래키·고유키·상태값·조회 인덱스를 업무 규칙에 맞게 보강한다.

- 기존 데이터는 회원 7건, 견적 요청 5건, 시공사 견적 1건, 알림 10건, 자재 36건으로 보존됐다.

### 백엔드 변경

- 역할이 중복되고 실사용 호출이 없는 `domain/schedule` 패키지 8개 소스와 `ScheduleNotFoundException`을 제거했다.
- 전역 예외 처리기의 schedule 전용 처리도 함께 제거했다.
- 현장 방문은 `site_visits`, 계약 후 공사 일정은 `contractor_projects`가 담당한다는 현재 구조에 맞춰 관련 주석만 정리했다.
- 프로젝트·리뷰·현장 방문의 업무 로직은 수정하지 않았다.
- 상세 설명은 `Docs/백엔드_최소테이블_정합화_안내.md`에 남겼다.

### 프론트엔드 변경

- 이번 단계에서 프론트엔드 코드는 수정하지 않았다.

### 검증 결과

- 백엔드 전체 테스트: 111건, 실패 0, 오류 0, 기존 스킵 1
- 프론트엔드 전체 테스트: 23건 통과
- 프론트엔드 프로덕션 빌드: 성공
- Vite의 약 730KB 메인 청크 경고는 기존 성능 개선 항목이며 빌드 실패는 아니다.
- `git diff --check`: 오류 없음

### 적용 중 발견하고 바로 해소한 항목

- 최초 백엔드 검증에서 삭제한 `ScheduleNotFoundException`의 전역 예외 처리 참조가 남아 컴파일 오류가 발생했다.
- 실DB 마이그레이션 전 단계에서 발견했으며 해당 죽은 참조를 제거한 뒤 전체 테스트를 다시 실행해 통과했다.

### 변경하지 않은 항목

- 프로젝트·리뷰 기능 코드와 프론트 화면은 건드리지 않았다.
- `ddl-auto=update`는 남은 명시적 마이그레이션이 끝날 때까지 유지한다.
- 커밋과 원격 푸시는 하지 않았다.
