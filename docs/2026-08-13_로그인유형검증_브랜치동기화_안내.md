# 로그인 유형 검증 및 브랜치 동기화 안내

## 수정 내용

### 1. 로그인 유형과 계정 역할 일치 검증

- 로그인 화면에서 선택한 `사용자`는 `LANDLORD` 계정만 로그인할 수 있습니다.
- 로그인 화면에서 선택한 `시공사`는 `CONTRACTOR` 계정만 로그인할 수 있습니다.
- 서버가 반환한 실제 역할과 선택 역할이 다르면 세션을 저장하거나 홈 화면으로 이동하지 않습니다.
- 불일치 시 `선택한 로그인 유형과 계정 유형이 일치하지 않습니다.`를 표시합니다.
- 역할 선택을 변경하면 이전 불일치 오류가 초기화됩니다.

### 2. 관리자 로그인 문구 제거

- 로그인 화면 하단의 `관리자 로그인` 문구를 삭제했습니다.
- 백엔드의 관리자 역할과 내부 기능은 이번 작업에서 삭제하지 않았습니다.

## 원인과 수정 방식

기존 화면은 사용자/시공사 선택 상태를 갖고 있었지만 로그인 성공 후 선택값을 확인하지 않고, 서버 응답 역할만 보고 해당 홈으로 이동했습니다. 이제 서버 응답을 받은 직후 선택 역할과 실제 역할을 비교하고, 일치할 때만 인증 세션 저장과 화면 이동을 실행합니다.

로그인 API 요청·응답 형식은 변경하지 않았으므로 기존 백엔드 및 다른 API 호출과 호환됩니다.

- 로그인 화면 회귀 테스트: 6개 통과
- 인증 API 관련 테스트 포함: 7개 통과
- 프론트엔드 전체: 41개 테스트 파일, 170개 테스트 통과
- ESLint: 오류·경고 없이 통과
- TypeScript 및 Vite 프로덕션 빌드: 통과
- 백엔드 전체 테스트: `BUILD SUCCESSFUL`

## 팀원 로컬 브랜치 갱신

원격 브랜치 동기화 후 각 팀원은 커밋하지 않은 작업을 먼저 커밋하거나 스태시하고 자기 브랜치에서 실행합니다.

```powershell
git fetch origin --prune
git pull --ff-only origin 자기브랜치명
```

예시:

```powershell
git switch frontend
git pull --ff-only origin frontend
```

`--ff-only`가 거절되면 로컬에 원격과 다른 커밋이 있는 상태이므로 강제로 덮어쓰지 말고 팀에 공유한 뒤 병합 또는 리베이스 방향을 정해야 합니다.
