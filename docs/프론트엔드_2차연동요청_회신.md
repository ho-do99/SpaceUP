## 2. 이미지 업로드 관련

- **기존 500 오류 수정** (커밋 `8dea71c`, 지난 배치): 상대 경로가 Tomcat 임시 디렉터리 기준으로 잘못 해석되던 버그. 업로드 → 200 응답(imageUrl) → 재조회 → 200(실제 바이트 확인)까지 실기동 재검증 완료.
- **20MB 초과 시 413**: 이번 배치에서 반영. `MaxUploadSizeExceededException`을 잡아 `413`으로 응답하며, 메시지는 `"파일 크기가 20MB를 초과했습니다."`.

## 3. 이미지 ↔ 의뢰 연결 (Option C로 구현)

말씀주신 A/B/C/D 안 중 **C안(전용 `RequestImage` 테이블/API)**으로 구현했습니다.

- `POST /api/requests/{requestId}/images` — body `{ imageType: "FLOOR_PLAN" | "PHOTO", imageUrl }`. `imageUrl`은 기존 `POST /api/files/images` 응답값을 그대로 전달하면 됩니다. 본인 의뢰만 가능.
- `GET /api/requests/{requestId}/images?imageType=FLOOR_PLAN` — `imageType` 생략 시 평면도+사진 전체 반환.
- `DELETE /api/requests/{requestId}/images/{imageId}` — 본인 의뢰 소속 이미지만 삭제 가능.

## 4. `PATCH /api/requests/{requestId}` — 의뢰 부분 수정

예산(`budgetMin`/`budgetMax`), 희망일정(`desiredDate`), 요청항목(`requestedItems`), 지역/주택유형/면적/보증금/월세 등 화면 뒤 단계에서 채워지는 필드를 나중에 저장할 수 있습니다. 모든 필드는 optional이며 넘긴 필드만 반영됩니다(부분 수정). 본인이 등록한 의뢰만 가능하며, 존재하지 않는 필드는 무시됩니다.

## 5. 공간별 분석 상세 저장 (AnalysisSpace)

- `PUT /api/analysis/request/{requestId}/spaces` — 공간(방) 목록을 통째로 교체 저장합니다(기존 목록 삭제 후 재삽입, 매 요청마다 전체 리스트 전송 필요). 각 공간: `spaceName`, `spaceAreaM2`, `floorAreaM2`, `wallpaperAreaM2`, `selectedForConstruction`(시공 대상 여부, 기본 true).
- `GET /api/analysis/request/{requestId}/spaces` — 저장된 공간 목록 조회.
- 시공 대상으로 표시된(`selectedForConstruction=true`) 공간들의 면적을 자동 합산해 `AnalysisJob`의 `totalFloorAreaM2`/`totalWallpaperAreaM2`(추천 상품 수량 계산에 사용)에 반영합니다. 추가로 `ceilingHeightM`(천장높이) 필드도 분석 기본정보 수정 API(`PATCH /api/analysis/request/{requestId}`)에 포함했습니다.

## 6. 추천 상품 API 보강

`GET /api/analysis/request/{requestId}/recommended-products` 응답에 다음 필드가 추가되었습니다:

`category`, `spec`, `brand`, `vendorName`, `imageUrl`, `unit`, `coverageM2`, `priority`(카테고리 내 순위)

- **조명/주방 상부장 카테고리 추가**: 기존 장판/벽지 2종에서 4종(FLOORING/WALLPAPER/LIGHTING/KITCHEN)으로 확장. 조명·주방은 면적이 아닌 개수 단위 상품이라 수량은 최소주문수량 기준입니다.
- **수량 계산 고도화**: 상품에 `coverageM2`(1단위 시공 가능 면적)가 등록돼 있고 해당 공간 면적 정보도 있으면 `ceil(면적 ÷ coverageM2)`로 실제 필요 수량을 계산합니다. 둘 중 하나라도 없으면 기존처럼 최소주문수량(없으면 1)으로 대체합니다.
- 상품 등록/수정 API(`POST/PUT /api/products`)에도 `imageUrl`/`unit`/`coverageM2` 입력 필드가 추가되었으니, 정확한 수량 계산을 원하시면 자재업체가 상품 등록 시 `coverageM2`를 채워야 합니다.

## 7. 테스트 계정 + 샘플 데이터

로그인: `POST /api/member/login`, 계정 3개 모두 비밀번호 `Test1234!`

| 계정 | username | role |
|---|---|---|
| 임대인 | `test_landlord` | LANDLORD |
| 시공사 | `test_contractor` | CONTRACTOR |
| 관리자 | `test_admin` | ADMIN |

`test_contractor`(memberId=2) 앞으로 아래 샘플 데이터를 실제 API 호출로 생성했습니다.

| 구분 | requestId | quoteId | scheduleId | 비고 |
|---|---|---|---|---|
| 배정된 의뢰 (미처리) | 2 | - | - | 상태 REVIEWING, 승인/거절 전 |
| 승인 가능한 의뢰 | 3 | - | - | 상태 REVIEWING — `POST /api/requests/3/approve` 테스트용 |
| 거절 가능한 의뢰 | 4 | - | - | 상태 REVIEWING — `POST /api/requests/4/reject` 테스트용 |
| DRAFT 견적 | 5 | 1 | - | 견적 임시저장 상태 |
| SUBMITTED 견적 | 6 | 2 | - | 견적 발송 완료 상태 |
| ACCEPTED 견적 + SCHEDULED 일정 | 7 | 3 | 1 | 견적 수락 완료, 착공일정 2026-09-20 SCHEDULED |
| IN_PROGRESS 일정 | 8 | 4 | 2 | 착공 시작 처리됨(IN_PROGRESS) |

기타:
- **PENDING 정산**: `settlementId=1` (partnerId=2, 거래금액 29,000,000원, 수수료 2,900,000원, 정산액 26,100,000원)
- **포트폴리오**: `portfolioId=1` ("강남 오피스텔 올리모델링")
- **알림**: 위 배정/견적/정산 액션들이 발생할 때마다 자동 생성되므로(`assignContractor`/`submit`/`accept`/정산 생성 등) `GET /api/notifications/me`로 시공사 계정에서 10건 이상 확인 가능합니다.

> 참고: 정산 생성(`POST /api/settlements`)은 ADMIN 권한으로만 가능합니다(관리자가 수기로 생성하는 화면 전제). LANDLORD/CONTRACTOR 토큰으로 호출하면 403이 발생하니, 정산 관련 프론트 화면 테스트 시 `test_admin` 계정을 사용해 주세요.

## 8. 이번 라운드에서 다루지 않은 항목 (정책 결정 필요)

아래 항목들은 백엔드 코드만으로 결정할 수 없는 사항이라, 구현 전에 방향을 먼저 정해야 합니다.

1. **AI/OCR 통합 계약**: 분석 파이프라인에 OCR/AI 이미지 인식을 어느 시점에 연동할지, 콜백 스펙을 어떻게 확장할지는 AI팀과 먼저 조율이 필요합니다.
2. **평면도 검색 방향**: 평면도 이미지 기반 검색을 이미지 유사도 검색으로 갈지, 태그/메타데이터 기반으로 갈지 방향이 정해져야 스키마를 설계할 수 있습니다.
3. **AI 인테리어 이미지 생성(Gemini)**: 아키텍처(Provider 인터페이스 + Gemini 구현체, 추후 OpenAI/Flux 등 확장 가능한 구조) 설계는 별도로 진행 예정이며, 실제 API 키 연동은 하지 않았습니다. **전달주신 API 키는 어떤 파일에도 하드코딩하지 않았고, 커밋하지도 않았습니다** — 이 저장소의 `application-local.yml`/`.env.local`/`.env.example`이 모두 git에 커밋되는 구조라, 환경변수 참조(`${GEMINI_API_KEY:}`) 방식이 아니면 키가 그대로 GitHub에 올라가기 때문입니다. 실제 연동 시에는 로컬에서만 별도로 `.env.local`에 값을 채워 넣는 방식을 권장드립니다.
4. **완전히 없는 기능(채팅/리뷰/현장방문 예약/공사 진행률 등)**: 각 기능의 화면 스펙(Figma)이 확정되면 순차적으로 스코프를 잡아 진행하겠습니다. 우선순위를 알려주시면 그 순서대로 진행하겠습니다.
