# 프론트엔드 로그인/API 연동 확인 회신

> 과거 연동 회신 기록입니다. 현재 회원 역할에는 `MATERIAL_VENDOR`가 없으며 최신 계약은 `Docs/Spaceup_백엔드_전체_API_문서.md`를 기준으로 합니다.

> 실제로 로컬에 MySQL(docker-compose) + 백엔드 서버를 띄우고, 로그인/이미지업로드/의뢰생성 API를 직접 호출해서 검증했습니다. 이 과정에서 이미지 업로드 API의 실제 버그(500 에러)를 발견해서 고쳤습니다 — 아래 7번 참고.

---

## 🔴 1순위

### 1. 백엔드 서버 실행 방법

| 항목 | 값 |
| --- | --- |
| 실행 클래스 | `com.spaceup.SpaceupApplication` (`backend/src/main/java/com/spaceup/SpaceupApplication.java`) |
| 실행 명령 | `backend/` 디렉터리에서 `./gradlew bootRun` |
| **정상 포트** | **8080이 맞습니다** (`${SERVER_PORT:8080}`). ⚠️ **이전에 8087로 안내드렸었는데, 최근 팀 저장소 구조 정비 과정에서 8080으로 바뀌었습니다.** docker-compose/nginx/frontend 프록시가 전부 8080 기준으로 이미 짜여 있어서 그쪽에 맞췄습니다. (제 로컬 PC에는 8080을 이미 쓰는 다른 프로그램이 있어서 테스트는 8090으로 임시 실행했습니다 — 코드 문제 아니고 제 PC 환경 문제입니다.) |
| Context Path | 없습니다 (`/` 기준, 실제 기동 로그로 확인: `Tomcat started on port 8090 (http) with context path ''` — 포트만 제 PC 사정으로 8090, context path는 빈 문자열입니다) |

**필요한 환경변수** (전부 기본값이 있어서 로컬 docker-compose로 띄우면 안 줘도 됩니다):

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `DB_HOST` / `DB_PORT` / `DB_NAME` / `DB_USER` / `DB_PASSWORD` | `localhost`/`3306`/`spaceup`/`spaceup_user`/`spaceup_password` | MySQL 접속 정보 |
| `SERVER_PORT` | `8080` | |
| `JWT_SECRET` / `JWT_EXPIRATION_MS` | (개발용 기본값 있음) / `3600000` | |
| `MOLIT_RENT_API_SERVICE_KEY` | 빈 문자열 | 국토부 실거래가 연동에만 필요, 로그인 테스트엔 무관 |

**DB 실행/연결**: 저장소 루트의 `docker-compose.local.yml`을 그대로 쓰시면 됩니다.
```bash
docker compose -f docker-compose.local.yml --env-file .env.local up -d db
```
**초기 데이터/SQL**: 별도로 실행할 SQL 없습니다. `ddl-auto: update`라 서버 처음 뜰 때 테이블이 자동 생성됩니다. `database/init.sql`은 그냥 `spaceup` 스키마(DB)만 만드는 용도입니다.

### 2. 테스트 계정

**실제로 만들어서 로그인까지 검증 완료했습니다.** 로컬 DB(docker-compose)에 아래 계정이 저장돼 있고, 서버를 그 DB로 띄우면 바로 쓰실 수 있습니다.

| role | username | password | memberId | 비고 |
| --- | --- | --- | --- | --- |
| LANDLORD | `test_landlord` | `Test1234!` | 1 | 탈퇴 아님, 로그인 가능 |
| CONTRACTOR | `test_contractor` | `Test1234!` | 2 | 승인대기(PENDING) 상태지만 **로그인은 됩니다**(승인 여부는 로그인을 막지 않음) |
| ADMIN | `test_admin` | `Test1234!` | 3 | 회원가입 API로는 못 만들어서(의도된 제한) SQL로 직접 시딩 |

이 계정들은 팀 저장소의 `docker-compose.local.yml` DB 볼륨에 저장돼 있어서, 그 컴포즈로 DB를 띄우면(다른 팀원 PC에서도) 계속 남아있습니다. 만약 새 환경에서 새로 만들어야 하면: LANDLORD/CONTRACTOR는 `POST /api/member/join`으로, ADMIN은 공개 API로 못 만들게 막혀있어서 DB에 직접 INSERT해야 합니다(비밀번호는 BCrypt 해시로).

### 3. 로그인 응답 실제 확인

**실제 호출 결과**, 프론트에서 예상하신 구조와 거의 같은데 **`message` 문자열에 느낌표가 붙습니다**:

```json
{
  "success": true,
  "message": "로그인 성공!",
  "data": {
    "accessToken": "eyJhbGciOiJIUzUxMiJ9...(JWT)",
    "memberId": 1,
    "role": "LANDLORD"
  }
}
```

- `accessToken` 필드명 정확합니다.
- `memberId`는 JSON number(long)입니다. `1`처럼 옵니다.
- `role`은 `LANDLORD` / `CONTRACTOR` / `MATERIAL_VENDOR` / `ADMIN` 중 하나 맞습니다(4종 — MATERIAL_VENDOR 포함).
- 로그인 요청에 `Authorization` 헤더 **없어도 됩니다** (실제로 안 보내고 테스트했고 정상 동작).
- **Access Token 만료 1시간 맞습니다** (발급된 토큰의 JWT payload `iat`/`exp` 차이가 정확히 3600초).
- **Refresh Token 미구현 맞습니다.** accessToken 하나만 발급되고, 만료되면 재로그인해야 합니다.
- 발급받은 토큰으로 `GET /api/member/{id}` 같은 인증 필요 API도 실제로 호출해서 정상 동작 확인했습니다.

### 4. CORS 허용 Origin

**`http://localhost:5173`, `http://127.0.0.1:5173` 둘 다 이미 허용돼 있습니다.** 실제 preflight(OPTIONS) 요청 두 origin 모두로 보내서 확인했고, 둘 다:
```
Access-Control-Allow-Origin: (요청한 origin 그대로)
Access-Control-Allow-Methods: GET,POST,PUT,PATCH,DELETE,OPTIONS
Access-Control-Allow-Headers: Authorization, Content-Type
Access-Control-Allow-Credentials: true
```
쿠키/credentials 방식은 안 쓰신다고 하셨는데, 서버 쪽은 `Access-Control-Allow-Credentials: true`로 설정돼 있습니다(문제 없음 — 안 써도 되고, 브라우저가 credentials 안 보내면 그냥 무시됩니다).

## 🟡 2순위

### 5. 의뢰 생성과 분석 요청 관계

**맞습니다. `POST /api/analysis/request/{requestId}`를 따로 호출하면 안 됩니다.** 실제 코드 확인 및 테스트 결과:

```java
// RequestController.create()
Long requestId = requestService.createRequest(landlordId, request);
analysisJobService.requestAnalysis(requestId); // ← POST /api/requests 안에서 자동 호출됨
```

실제로 `POST /api/requests` 호출 직후 `GET /api/analysis/request/{requestId}`를 바로 호출해보니 `"status":"PENDING"`인 AnalysisJob이 이미 만들어져 있었습니다. 프론트가 계획하신 흐름(`POST /api/requests` → `requestId` 저장 → `GET /api/analysis/request/{requestId}`로 상태 폴링) 그대로 맞습니다.

`POST /api/analysis/request/{requestId}`는 **ML 파이프라인(외부 AI 서버)이 콜백으로 쓰는 용도가 아니라**, 그 반대로 `/result`, `/fail`이 콜백이고, 이 POST 자체는 "재분석을 처음부터 다시 요청"하고 싶을 때만 쓰는 용도입니다(예: 관리자가 수동으로 재시도시킬 때). 일반 사용자 플로우에서는 호출할 일이 없습니다.

### 6. `POST /api/requests` 호출 시점

코드 확인 결과 `RequestCreateRequest`에서 **필수값은 `region`, `propertyType`, `areaM2` 3개뿐**입니다. `budgetMin`/`budgetMax`/`desiredDate`/`requestedItems`는 전부 선택(nullable)이라, 실제로 이 3개만 넣고 호출해봤더니 정상 생성됐습니다.

**다만 확인드릴 게 있습니다: 의뢰 수정(PATCH/PUT) API가 실제로 없습니다.** 그래서 세 가지 옵션을 그대로 검토하면:

- **A. 최소 정보만으로 생성** — 기술적으로는 됩니다. 다만 `budgetMin/budgetMax`가 없으면 "예비 임대가치 상승분" 계산과 시공사 매칭 점수의 "예상 견적 적합도"가 전부 0/누락 처리됩니다. `desiredDate`가 없으면 매칭 점수의 "일정 적합도"도 마찬가지입니다. 나중에 값을 채워 넣을 방법이 지금은 없어서, **한 번 최소 정보로 생성하면 예산/일정은 영영 비어있게 됩니다.**
- **B. 화면 끝까지 다 받고 생성** — 이게 지금 API 스펙엔 가장 안전하지만, "AI 분석" 화면이 "예산·희망 일정 입력" 화면보다 앞에 있는 프론트 흐름과 안 맞습니다(분석을 시작하려면 requestId가 필요한데, requestId는 맨 마지막에나 생김).
- **C. 최소 생성 + 나중에 의뢰 수정 API로 보완** — **가장 프론트 흐름에 맞는데, 이 수정 API가 아직 없습니다.**

**제 의견은 C입니다.** `PATCH /api/requests/{requestId}`(예산/희망일정/요청항목만 갱신) 같은 걸 추가하는 게 필요해 보이는데, 이건 새 API라 제가 임의로 만들지 않고 여쭤보고 진행하겠습니다 — 필요하시면 바로 작업할 수 있습니다.

### 7. 이미지 업로드 API 계약

**실제로 호출해보다가 500 에러 버그를 발견해서 고쳤습니다.** (상대경로 저장 위치를 절대경로로 변환 안 해서 나던 문제 — 수정 후 재테스트 완료, `backend` 브랜치에 커밋 `8dea71c`로 반영/push 했습니다.)

```
POST /api/files/images
Content-Type: multipart/form-data
Authorization: Bearer {accessToken}   ← 필요합니다 (없으면 403)

Part:
- file: MultipartFile   ← part 이름이 "file"입니다("image" 아님)

Response (200):
{
  "success": true,
  "message": "이미지가 업로드되었습니다.",
  "data": {
    "imageUrl": "/api/files/images/3fb17c1e-8b31-4cb2-8a37-8cdc1707d5af.png"
  }
}
```

- **파일 외 추가 Part 없습니다.** `file` 하나만 받습니다.
- **허용 확장자**: 고정 목록이 아니라 업로드된 파일의 Content-Type이 `image/`로 시작하기만 하면 허용됩니다(png/jpeg/gif/webp 등). 아닌 파일 보내면:
  ```
  400 { "success": false, "message": "이미지 파일만 업로드할 수 있습니다." }
  ```
- **최대 파일 크기**: 20MB (`spring.servlet.multipart.max-file-size`). ⚠️ 20MB 넘는 파일을 보내면 지금은 500(일반 오류)으로 떨어집니다 — 413 같은 명확한 코드로 못 바꾼 상태입니다, 필요하시면 고쳐드리겠습니다.
- **`imageUrl`은 상대 경로**입니다(`/api/files/images/{파일명}`). Base URL(`http://localhost:8080`)을 프론트에서 앞에 붙여서 `<img src>`에 쓰시면 됩니다. 이 GET 엔드포인트는 인증 없이 접근 가능합니다(이미지 태그가 Authorization 헤더를 못 보내서 일부러 공개해뒀습니다).
- 업로드 실패(인증 없음): `403`. 업로드 실패(비이미지): `400`.

## 🟢 3순위

### 8. 아파트 평면도 검색 API

**아직 없습니다.** 코드에 해당 도메인 자체가 없습니다 — 외부 아파트 API 연동, 자체 DB, mock 중 뭘로 갈지 아직 팀 차원에서 결정이 안 된 상태로 보입니다(팀 저장소에 `floorplan`이라는 빈 패키지 자리만 있음). 지금 프론트에서 mock으로 시연해두신 게 맞는 방향입니다. 방향 정해지면 알려주세요.

### 9. AI 인테리어 이미지 생성 API

**아직 없습니다.** `domain/analysis`는 "평면도/사진 분석 결과"(방 개수, 점수 등)만 받는 구조지, 스타일 변환된 이미지를 생성/반환하는 기능은 없습니다. 팀 저장소에 `ai/` 서비스(FastAPI)가 별도로 존재하긴 하는데, 현재 Spring 백엔드가 그걸 중계하는 코드는 없습니다. 프론트가 지금처럼 "생성 중" 화면을 정지 상태로 유지하시는 게 맞습니다. 이것도 계약 확정되면 바로 작업 가능합니다.

### 10. 시공사·포트폴리오 ID 기준

**둘 다 동일한 ID 기준이고, `Member.memberId`(로그인 응답의 `memberId`와 같은 값)입니다.** `ContractorProfile.id`가 아닙니다. 코드로 확인:
```java
// ContractorProfileService.getPublicProfile
contractorProfileRepository.findByMemberId(contractorId)  // ← memberId로 조회
// Portfolio.contractor는 Member 참조 (contractor_id 컬럼이 user_account.user_id를 가리킴)
```
`GET /api/requests/{id}/recommended-contractors` 응답의 `contractorId`도 같은 값이라, 추천 목록에서 받은 `contractorId`를 그대로 `GET /api/contractors/{id}`, `GET /api/portfolios/contractor/{id}`에 넣으면 됩니다.

### 11. 추천 상품 API 응답 DTO

⚠️ **엔드포인트 경로에 오타가 있습니다.** 요청하신 건 `/api/analysis/requests/{requestId}/recommended-products`(복수형 "requests")인데, 실제로는 **`/api/analysis/request/{requestId}/recommended-products`(단수형 "request")**입니다. 인증 필요합니다.

```json
{
  "success": true,
  "message": "추천 상품 조회 완료",
  "data": [
    {
      "productId": 1,
      "productName": "string",
      "vendorName": "string",
      "imageUrl": null,
      "unitPrice": 15000,
      "quantity": 10,
      "amount": 150000,
      "reason": "string"
    }
  ]
}
```
- 배열 하나에 FLOORING/WALLPAPER 상품이 섞여서 들어갑니다(카테고리별 별도 필드 아님) — 필요하시면 프론트에서 `productName`/`reason`으로 구분하시거나, 카테고리 필드를 추가해드릴 수 있습니다(지금은 응답에 카테고리 필드가 없습니다).
- 수량 필드: `quantity` (있습니다)
- 가격 필드: `unitPrice`(단가), `amount`(단가×수량)
- 추천 이유: `reason`
- `imageUrl`: 필드는 있지만 **항상 `null`**입니다 — 상품 테이블에 이미지 컬럼이 아직 없어서입니다(백로그 항목).
- 분석 미완료/상품 없음이어도 에러 안 나고 **빈 배열**이 옵니다(실제 테스트 확인). 의뢰 자체가 없으면 `404`.
- **말씀하신 대로 조명(LIGHTING) 추천은 이 API에 포함 안 됩니다.** FLOORING/WALLPAPER만 추천합니다.
