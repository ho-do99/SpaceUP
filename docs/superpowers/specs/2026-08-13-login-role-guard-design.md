# 로그인 유형 검증 및 관리자 문구 제거 설계

## 목표

- 사용자가 선택한 로그인 유형과 실제 계정 역할이 다르면 로그인되지 않게 한다.
- 로그인 화면 하단의 `관리자 로그인` 문구를 제거한다.
- 기존 로그인 API 계약과 역할별 정상 로그인 경로는 유지한다.

## 원인

로그인 화면은 `LANDLORD`와 `CONTRACTOR` 선택 상태를 관리하지만, 인증 성공 후 서버가 반환한 실제 `role`만 보고 이동한다. 선택 상태와 응답 역할을 비교하지 않기 때문에 어느 유형을 선택해도 올바른 이메일과 비밀번호만 입력하면 로그인된다.

## 설계

로그인 응답을 받은 직후 선택한 `loginRole`과 `loginResponse.role`을 비교한다. 두 값이 다르면 인증 세션을 저장하지 않고 화면 이동도 하지 않으며, `선택한 로그인 유형과 계정 유형이 일치하지 않습니다.` 오류를 표시한다. 두 값이 같을 때만 세션을 저장하고 `LANDLORD`는 `/`, `CONTRACTOR`는 `/contractor`로 이동한다.

백엔드는 이미 실제 계정 역할을 신뢰할 수 있는 로그인 응답에 포함하고 있고 JWT 권한도 실제 역할로 발급한다. 따라서 이번 수정은 로그인 API 요청 형식을 변경하지 않고 프론트에서 선택 역할을 검증해 기존 클라이언트 호환성을 보존한다.

화면 하단의 `관리자 로그인` 텍스트 요소는 삭제한다. 관리자 계정이나 백엔드 역할 자체는 이번 작업 범위에서 삭제하지 않는다.

## 오류 처리

- 역할 불일치는 자격 증명 오류와 구분되는 명시적인 화면 오류로 표시한다.
- 역할 불일치 응답의 토큰은 `sessionStorage`에 저장하지 않는다.
- 사용자가 역할·이메일·비밀번호를 변경하면 기존 오류를 지운다.

## 테스트

- 사용자 선택 + 시공사 응답: 오류 표시, 세션 미저장, 이동 없음.
- 시공사 선택 + 사용자 응답: 오류 표시, 세션 미저장, 이동 없음.
- 사용자 선택 + 사용자 응답: 사용자 홈 이동.
- 시공사 선택 + 시공사 응답: 시공사 홈 이동.
- 로그인 화면에서 `관리자 로그인` 문구가 렌더링되지 않음.

## 브랜치 반영

`ai`에서 전체 테스트·린트·빌드를 통과시킨 뒤 `main`을 Fast-forward로 갱신한다. 이후 `develop`, `frontend`, `backend`, `infra` 원격 브랜치를 같은 커밋으로 Fast-forward 동기화하며 강제 푸시는 사용하지 않는다.
