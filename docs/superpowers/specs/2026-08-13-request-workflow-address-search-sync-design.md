# 요청 흐름·주소 검색·브랜치 동기화 설계

## 목표

- 아파트 등록 평면도와 빌라 직접 업로드에서 발생하는 중복 분석 작업 HTTP 409를 제거한다.
- 시공사 계정설정의 로그아웃을 활성화하고 인증·요청 세션을 함께 제거한다.
- 주소 검색 결과를 평면도 카탈로그 보유 여부와 분리한다.
- 검증된 `ai` 변경만 `main`에 반영하고 팀 브랜치를 강제 푸시 없이 동기화한다.

## 사용자 흐름

```text
검색어 입력 → Kakao 공식 주소 검색 결과 → 주소 선택
  ├─ SpaceUP 등록 평면도 있음
  │   → 면적 선택 → 요청 생성 → 분석 작업 1회 생성 → 등록 도면 AI 분석
  └─ SpaceUP 등록 평면도 없음
      → 전용면적 입력 → 요청 생성 → 평면도 업로드
      → 분석 작업 1회 생성 → 업로드 도면 AI 분석
```

주소 검색은 Kakao 우편번호 서비스를 사용한다. 이 서비스는 API 키가 필요 없고 현재 프로젝트의 회원가입 주소 입력에서 이미 사용 중이다. 사용자가 입력한 검색어는 `open({ q })`로 전달한다. 선택 결과의 도로명주소·지번주소·건물명을 저장한 뒤 SpaceUP 평면도 카탈로그를 별도로 조회한다. 카탈로그 미등록 주소도 선택 상태를 유지한다.

## 분석 작업 계약

`POST /api/requests`는 의뢰만 생성한다. `POST /api/analysis/request/{requestId}`가 분석 작업 생성의 유일한 진입점이다. 같은 요청에 기존 작업이 있으면 소유권 확인 후 기존 ID를 반환한다. `analysis_job.request_id` UNIQUE 제약은 유지한다.

동시 호출은 의뢰 행을 비관적 쓰기 잠금으로 직렬화한다. 프론트엔드 제출 버튼 비활성화와 별개로 백엔드가 멱등성을 보장한다.

## 로그아웃 계약

두 시공사 설정 화면은 하나의 확인 다이얼로그를 공유한다. 확인 시 다음 값을 제거한 후 `/login`으로 replace 이동한다.

- `accessToken`
- `memberId`
- `role`
- 진행 중 의뢰 초안과 활성 request ID

취소 시에는 어떤 세션 값도 변경하지 않는다.

## Git 통합 계약

1. 최신 `origin/ai`에서 격리 worktree 작업
2. 백엔드·프론트 전체 테스트, 린트, 빌드 통과
3. `ai` 푸시
4. 원격을 다시 fetch하고 `main`에 새 커밋이 없는지 확인
5. `main`을 `ai`까지 fast-forward한 뒤 재검증·푸시
6. `develop`, `frontend`, `backend`, `infra`가 새 `main`의 조상이면 fast-forward 푸시
7. 어느 브랜치든 팀원의 새 커밋이 생겼거나 fast-forward가 불가능하면 강제 푸시하지 않고 중단

## 테스트 기준

- 의뢰 생성 API가 분석 서비스에 부수효과를 만들지 않는다.
- 분석 시작을 재요청하면 기존 작업 ID를 반환한다.
- 공식 주소 선택은 평면도 카탈로그가 비어 있어도 직접 업로드로 이어진다.
- 등록 평면도가 있으면 선택 variant ID와 분석 작업 ID가 로딩 화면에 전달된다.
- 두 시공사 설정 화면의 로그아웃이 인증·요청 세션을 제거한다.
- 기존 회원가입 주소 검색 동작은 유지한다.
